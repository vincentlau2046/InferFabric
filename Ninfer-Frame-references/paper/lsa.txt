 Ultra-Long Context Attention

 Preprint. 
 Abstract 

 Agentic workflows are increasingly shifting towards long-horizon tasks, such as open-ended scientific work, where models benefit from long context windows.
However, at ultra-long context (above 1M tokens), full attention is prohibitively expensive. A promising approach is sparse attention, in which a dedicated indexer selects a subset of keys for the attention. Yet current methods of indexing either still have quadratic cost in context size or lose accuracy at ultra-long context scale.
We address this with Latent Sparse Attention (LSA), an efficient attention method that maintains accuracy at ultra-long context. In LSA, keys are hierarchically clustered in a learned latent space, and queries score the hierarchy of clusters instead of scoring every key, making prefill, decode and training faster at long context.
We propose two variants, Distilled-LSA (D-LSA), which can be applied to pre-trained models via distillation, and Native-LSA (N-LSA), which is trained natively on the next-token loss alone.
On GLM-5.3-Flash ( Qwen-3.8-27B ) at 10M tokens, D-LSA speeds up one attention layer by 22.7 × 22.7\times ( 72.4 × 72.4\times ) in prefill and 4.6 × 4.6\times ( 42.5 × 42.5\times ) in decode over its original sparse attention (full attention), while keeping similar accuracy across a variety of tasks.
N-LSA matches the accuracy of full attention with a training speedup of 1.6 × 1.6\times per layer at 128k tokens.
LSA offers practical and efficient attention for models to benefit from ultra-long context. 

 1 Introduction

 Large language models have moved from answering single requests to agentic workflows in long-horizon tasks, such as software engineering and open-ended scientific research  ( Jimenez et al., 2024 ; Lu et al., 2026 ) .
These tasks keep growing in length  ( Kwa et al., 2025 ) , and models with longer context windows tend to score higher on them  ( Zhu et al., 2026 ) .
In line with this trend, recent models extend their context windows to 1M tokens and beyond  ( Gemini Team, 2024 ; MiniMax, 2025 ; DeepSeek-AI, 2026a ; Qwen Team, 2026a ) . 

 At this context size, attention dominates the cost, as its work grows with context  ( Vaswani et al., 2017 ; Dao et al., 2022 ) .
An established technique to reduce such costs is sparse attention  ( Hoefler et al., 2021 ) , in which each query attends to only a subset of the keys, chosen by a fixed pattern  ( Child et al., 2019 ; Beltagy et al., 2020 ; Zaheer et al., 2020 ) , by their content  ( Kitaev et al., 2020 ; Roy et al., 2021 ) , or by a dedicated indexer  ( Yuan et al., 2025 ; DeepSeek-AI, 2025 ) .
Recent frontier models are increasingly adopting sparse attention, in which keys are selected using a dedicated indexer  ( DeepSeek-AI, 2025 ; Qwen Team, 2026a ) . 

 However, current indexers still score every preceding key, or block of keys, for each query. This remains expensive (quadratic in prefill, linear in decode), and becomes a bottleneck at long context  ( Zan et al., 2026 ; Xu et al., 2026 ) . For example, at 10M tokens, 98% of the prefill time of a sparse attention layer is spent on indexing (Figure  2 ).
The cost of sparse attention at ultra-long context is therefore dominated by the cost of finding the keys. 

 To address this, we introduce Latent Sparse Attention (LSA), which clusters keys in a learned latent space and lets each query search the clusters instead of scoring every key. This can be done using only one level of clustering ( Flat ), or with a hierarchy of clusters ( Tree ), which makes the prefill subquadratic.
Furthermore, we propose two trainable designs: D-LSA, which adds LSA to pre-trained models and only trains small projection matrices per layer (contribution #1) , and N-LSA, which trains LSA natively with the Next-Token Prediction (NTP) loss alone (contribution #2) .
We evaluate state-of-the-art models ( Qwen-3.8-27B and GLM-5.3-Flash ) beyond their advertised context, up to 10M tokens (contribution #3) , on RULER  ( Hsieh et al., 2024 ) , which is an established long-context benchmark, and PaperTrail, which we developed to test long-context scientific understanding by finding and connecting facts across unseen scientific papers (contribution #4) .
Finally, we integrate LSA into SGLang  ( Zheng et al., 2024 ) 1 1

 2 Sparse Attention 

 In full attention, every query attends to every preceding key.
Prefilling a context of T T tokens therefore costs 𝒪 ⁡ ( T 2 ) \mathcal{O}(T^{2}) , and decoding one token costs 𝒪 ⁡ ( T ) \mathcal{O}(T) . In sparse attention, the work is split between an indexer and the attention. For each query, the indexer selects which keys the attention attends to 3 3 
 3 

 In this view, full attention corresponds to an indexer that returns the indices of all preceding keys. . With a fixed budget of k k keys, the attention then costs 𝒪 ⁡ ( T ​ k ) \mathcal{O}(Tk) to prefill and 𝒪 ⁡ ( k ) \mathcal{O}(k) per decoded token. If the indexer selects the most relevant keys, this is sufficient to stay close to the accuracy of full attention (Appendix  A ). 

 However, the indexer has a cost. Since it must score all preceding keys, it typically remains 𝒪 ⁡ ( T 2 ) \mathcal{O}(T^{2}) in prefill and 𝒪 ⁡ ( T ) \mathcal{O}(T) in decode, though with reduced constant factors. This makes ultra-long context still prohibitively expensive. For example, at 10M tokens the indexer takes 98% of the prefill time of traditional sparse attention (Figure  2 ), and a ‘free’ indexer would make sparse attention a further 58 × 58\times faster in prefill and 8.9 × 8.9\times in decode.

One global attention layer of GLM-5.3-Flash (512k to 10M tokens) on one H200, prefilling the last chunk of 32,768 queries and decoding one token.  2.1 Design Choices 

 Sparse attention methods can be categorised by their indexer designs and how they are trained. 

 Token Sparse Attention. 
For each query, a lightweight indexer (fewer heads, smaller dimension, lower precision) scores every preceding key and selects which to attend to. 

 Block Sparse Attention. 
Consecutive keys are grouped into blocks, and each query scores blocks instead of every key.
All keys of the selected blocks are sent to the attention. 

 Semantic Sparse Attention. 
Keys are clustered by similarity rather than position, and each query scores one centroid per cluster.
All keys of the selected clusters are sent to the attention. 

 For the last two categories, a query can search the groups in three ways. Flat search scores every group directly, which is 𝒪 ⁡ ( T ) \mathcal{O}(T) work per query. Fixed search adds a shallow hierarchy and refines from coarse to fine groups, which is also 𝒪 ⁡ ( T ) \mathcal{O}(T) per query. Tree search descends a deeper hierarchy and expands only the groups it keeps at each level, which is 𝒪 ⁡ ( log ⁡ T ) \mathcal{O}(\log T) per query. 

 An indexer can be training-free, distilled from a pre-trained model, or trained natively on the NTP loss alone.

 Table  1 provides an overview of the existing work on sparse attention, as categorised above.
We focus on methods that keep the whole KV cache and select keys per query, unlike fixed sparse patterns  ( Child et al., 2019 ; Beltagy et al., 2020 ; Zaheer et al., 2020 ) and KV cache eviction techniques  ( Zhang et al., 2023b ; Li et al., 2024 ; Xiao et al., 2024b ) . 

 Among distillation methods, DSA  ( DeepSeek-AI, 2025 ) and MiniMax SA  ( Lai et al., 2026 ) first distil the indexer and then continue training the full model under sparse attention.
Alternatively, SeerAttention  ( Gao et al., 2025 ; Gao et al., 2026 ) distils a gate over pooled blocks and HashAttention  ( Desai et al., 2025 ) learns binary codes of queries and keys, both with the model frozen.
As the context grows, the indexer itself becomes the bottleneck  ( Xu et al., 2026 ; Zan et al., 2026 ; Bai et al., 2026 ) .
To reduce its cost, CSA  ( DeepSeek-AI, 2026a ) , QSA  ( Qwen Team, 2026a ) , and GLM-5.3-Flash SA  ( Z.ai, 2026 ) compress every four keys into one before scoring them.
HISA  ( Xu et al., 2026 ) and LongCat LSA  ( Zan et al., 2026 ) score blocks first and then only the keys inside the selected blocks.
IndexCache  ( Bai et al., 2026 ) , LongCat LSA and DeepSeek-V4.1  ( DeepSeek-AI, 2026b ) reuse the selection of one layer in the following layers.
Each improvement divides the cost of the indexer by a constant, and its work per query therefore still grows linearly with the context. 

 NSA  ( Yuan et al., 2025 ) and MoBA  ( Lu et al., 2025 ) instead pre-train the model with sparse attention from scratch, such that the indexer learns from the NTP loss alone.
NSA scores each block by a learned compressed key, and MoBA by the mean of its keys.
InfLLM-V2  ( Zhao et al., 2026 ) and SSA  ( Mao et al., 2026a ) bring such block selection to existing dense models by fine-tuning.
HSA  ( Hu et al., 2025 ; Leng et al., 2026 ; Hu et al., 2026a ) and HSA-UltraLong  ( Hu et al., 2026b ) also weight the output of each block by its score, such that the loss trains the scores directly.
All of these methods still scan every block.
PISA  ( Tang et al., 2026 ) replaces this scan with a tree, but evaluates accuracy only at small scale (up to 16k tokens). 

 At the other end, Quest  ( Tang et al., 2024 ) , InfLLM  ( Xiao et al., 2024a ) and MInference  ( Jiang et al., 2024 ) select blocks based on simple summaries of their keys without any training.
HiP  ( Lee et al., 2025a ) searches the blocks with a tree, and its successor InfiniteHiP  ( Lee et al., 2025b ) with three fixed stages.
BLASST  ( Yuan et al., 2026 ) instead skips blocks directly inside the attention kernel, without a dedicated indexer.
Most of these methods summarise blocks of consecutive keys, which may hide a single relevant key  ( Xiao et al., 2024a ; Hu et al., 2026a ) . 

 Closest to LSA are methods that organise the keys by semantic content rather than by position.
A few early works train at short context, with Reformer  ( Kitaev et al., 2020 ) hashing keys into buckets, Routing Transformer  ( Roy et al., 2021 ) learning k-means centroids, and Treeformer  ( Madaan et al., 2023 ) routing each query down a learned tree.
Most other works here only operate at inference time: ClusterKV  ( Liu et al., 2025b ) and RetroInfer  ( Chen et al., 2026 ) cluster the keys during prefill and score every centroid at decode (flat search), Squeezed Attention  ( Hooper et al., 2025b ) , Multipole Attention  ( Hooper et al., 2025a ) and LycheeCluster  ( Li et al., 2026 ) search two levels (fixed search), and IceCache  ( Mao et al., 2026b ) descends a tree of keys (tree search), while RetrievalAttention  ( Liu et al., 2025a ) links the keys in a nearest-neighbour graph.
All of these inference methods are training-free, only Squeezed Attention speeds up prefill, and only partially, and none are evaluated at ultra-long context (above 1M tokens).

 3 Latent Sparse Attention (LSA) 

 LSA is a sparse attention layer for ultra-long context.
It clusters keys by content, in a space that is learned: through index projections in D-LSA, and through the attention’s own keys in N-LSA.
LSA can replace the attention of a pre-trained layer by distillation (D-LSA) or be trained natively with the model (N-LSA). 

 In both settings, the indices for the attention are selected from the keys and queries by the same process.
We first describe this process, numbered as in Figure  3 , which consists of semantic clustering of the index keys k j ( idx ) k_{j}^{(\mathrm{idx})} , and the search with the index queries q i ( idx ) q_{i}^{(\mathrm{idx})} so that each query selects its keys.
We then describe the specifics of D-LSA and N-LSA. 

 3.1 Semantic Clustering 

 1 
 Key normalisation. 
Each index key k j ( idx ) k_{j}^{(\mathrm{idx})} is first L2 normalised: k j ( idx ) ← k j ( idx ) ∥ k j ( idx ) ∥ k_{j}^{(\mathrm{idx})}\leftarrow\frac{k_{j}^{(\mathrm{idx})}}{\lVert k_{j}^{(\mathrm{idx})}\rVert} 

 2 
 Pooling. 
Consecutive keys are then compressed, as in CSA  ( DeepSeek-AI, 2026a ) , QSA  ( Qwen Team, 2026a ) and GLM-5.3-Flash SA  ( Z.ai, 2026 ) , to improve computational efficiency. Here, every n pool n_{\mathrm{pool}} consecutive index keys are summed into one pool key k pool ( idx ) k_{\mathrm{pool}}^{(\mathrm{idx})} , so that clustering runs over T / n pool T/n_{\mathrm{pool}} pool keys rather than T T keys. 

 3 
 Clustering. 
Keys are clustered in cluster blocks of n cluster n_{\mathrm{cluster}} consecutive keys.
Once a cluster block contains all its keys, its pool keys are clustered bottom up with Ward’s method  ( Ward, 1963 ) into m m buckets (Algorithm  1 in Appendix  B ).
Each pool key starts as a bucket of its own, and each bucket keeps the sum of its keys, whose normalisation is its centroid c b c_{b} .
In every round, all pairs of buckets that are each other’s cheapest merge are merged in parallel.
The cost of a merge is how much it increases the keys’ total squared distance from their centroid (Ward’s criterion).
Merging stops once there are m = n cluster / n ¯ b m=n_{\mathrm{cluster}}/\bar{n}_{b} buckets, where n ¯ b \bar{n}_{b} is the average number of keys per bucket, such that every cluster block holds the same number of buckets.
A merge is skipped if the merged bucket would hold more than n b max n_{b}^{\mathrm{max}} keys. 

 4 
 Bucket cache. 
The bucket cache B cache ( idx ) B_{\mathrm{cache}}^{(\mathrm{idx})} stores the centroid c b c_{b} of every bucket and an index table of the positions of its keys. This is so later selected buckets can ‘expand’ into their key indices. With one centroid per n ¯ b \bar{n}_{b} keys, it corresponds to a small fraction of the KV cache. 

 Once a cluster block is clustered, its buckets never change. In the Tree variant, this clustering process is repeated to group the buckets into multiple levels of a hierarchy. 

 3.2 Semantic Search 

 We now describe how the top- k k key indices are extracted for each query, and then submitted to attention. We first describe the process for Flat , in which there is only one level of buckets, and then discuss Tree . 

 A 
 Query normalisation. 
Each index query q i ( idx ) q_{i}^{(\mathrm{idx})} is first L2 normalised: q i ( idx ) ← q i ( idx ) ∥ q i ( idx ) ∥ q_{i}^{(\mathrm{idx})}\leftarrow\frac{q_{i}^{(\mathrm{idx})}}{\lVert q_{i}^{(\mathrm{idx})}\rVert} 

 B 
 Scoring. 
The index query scores the unit-norm centroid of every bucket in the cluster blocks before its own via s i , b = c b ⋅ q i ( idx ) s_{i,b}=c_{b}\cdot q_{i}^{(\mathrm{idx})} , which compares buckets of any size on one scale, and selects the top- p p buckets.
Its own cluster block is not clustered yet, and its keys are covered by the window instead. 

 C 
 Expansion. 
The selected p p buckets are expanded into their keys, best first, until k k ‘long-range’ keys are selected.
As every bucket holds at least n pool n_{\mathrm{pool}} keys, p p is chosen such that p ⋅ n pool ≥ k p\cdot n_{\mathrm{pool}}\geq k , and so expansion always fills k k keys. 

 Besides the k k long-range keys, every query attends to n sink n_{\mathrm{sink}} sink keys  ( Xiao et al., 2024b ) and the n w n_{w} most recent keys (window).
A key of a selected bucket that falls in the sink or the window is already attended to, and the expansion moves on to the next key instead.
We set the window to one cluster block, n w = n cluster n_{w}=n_{\mathrm{cluster}} , so that the window covers every key not yet clustered.
This gives each query i i a set J i J_{i} of at most n sink + k + n w n_{\mathrm{sink}}+k+n_{w} key indices. 

 D 
 Attention. 
Attention is then computed only over the keys indexed by J i J_{i} . A single J i J_{i} is shared across all query heads. 

 Tree search arranges the buckets into a hierarchy (Figure  3 , right).
Level 0 holds the buckets, and each higher level ℓ ≥ 1 \ell\geq 1 holds buckets we term ‘node buckets’, each made of n b , ℓ n_{b,\ell} buckets of the level below, with a centroid over all the keys it contains.
As at level 0, buckets are merged one cluster block at a time.
Buckets that are not merged yet are defined as open.
Once a level holds n cluster , ℓ n_{\mathrm{cluster},\ell} open buckets, they are merged into node buckets as in Algorithm  1 . 

 Beam search is used to select the buckets through the hierarchy (Algorithm  2 in Appendix  B ).
On each level, the query is scored against the centroids of the candidate node buckets, and the best p ℓ p_{\ell} are kept.
The candidates on the level below are the children of the kept node buckets and the open buckets of that level.
At level 0, the top- p p buckets are selected, as in the flat search.
With a constant beam per level, a query scores 𝒪 ⁡ ( log ⁡ T ) \mathcal{O}(\log T) centroids, which makes the prefill of the indexer subquadratic, 𝒪 ⁡ ( T ​ log ⁡ T ) \mathcal{O}(T\log T) , where the flat search is quadratic. 

 3.3 D-LSA 

 D-LSA (Figure  3 ) follows the process outlined above, but since it distils from a pre-trained model which already has key and query projections ( k j ( attn ) k_{j}^{(\mathrm{attn})} and q i ( attn ) q_{i}^{(\mathrm{attn})} ), we additionally learn separate key and query projections for LSA. In particular, each key k j ( attn ) k_{j}^{(\mathrm{attn})} and query q i ( attn ) q_{i}^{(\mathrm{attn})} is projected to a smaller dimension d ( idx ) d^{(\mathrm{idx})} to keep the scoring, clustering, and bucket cache cheap:

 The query heads are summed such that one index query serves every head, which yields the single index list J i J_{i} per query.
On Qwen-3.8-27B , whose keys and queries carry RoPE  ( Su et al., 2024 ) on a quarter of their dimensions, the projections read only the RoPE-free part.
These keys and queries then go into the normalisation process as before.
Trainable projections can also be replaced by the leading d ( idx ) d^{(\mathrm{idx})} principal directions of the keys in the layer, which project both keys and queries into one index space with no training.
We call this variant D-LSA (Training-Free). 

 The base model’s attention is otherwise unchanged: its own queries attend only to the keys and values indexed by J i J_{i} . 

 Distillation. 
D-LSA adds LSA to a pre-trained model by a short distillation that trains only W Q , K ( idx ) W_{Q,K}^{(\mathrm{idx})} and a temperature τ \tau per layer, with the base model frozen.
This mirrors the dense warm-up of DSA  ( DeepSeek-AI, 2025 ) , which also trains only the indexer against the head-aggregated attention of the frozen model.
The distillation scores every key directly, without clustering.
For a query i i of a layer, let ℛ i \mathcal{R}_{i} be the keys it can select (all preceding keys outside the sink and the window).
The target A i A_{i} is the attention of that frozen layer over ℛ i \mathcal{R}_{i} , the softmax of each head’s logits over ℛ i \mathcal{R}_{i} averaged over its n h n_{h} heads of dimension d h d_{h} , and A ^ i \hat{A}_{i} is the softmax of the D-LSA scores over the same keys.
The distillation minimises the forward KL divergence between the two:

 The temperature τ \tau sharpens the softmax of the D-LSA scores to match the peaked attention of the model, and is used only in this loss.
Both projections are initialised with these principal directions. 

 Kernels. 
We write GPU kernels for the clustering, scoring, selection and expansion of the indexer, in CuTe DSL for H200 and B300, with a Triton version of each, which runs on any GPU.
For the attention, we reuse existing attention kernels, such as FlashAttention-3  ( Shah et al., 2024 ) , which read the index list J i J_{i} as a page table. 

 Parallelism. 
We integrate LSA into SGLang with support for tensor, expert, and pipeline parallelism, and for context parallelism in both prefill and decode.
Context parallelism splits the KV cache across ranks by token, but LSA replicates its bucket cache on every rank.
Every rank thus builds the same index and selects the same index list. The ranks only exchange the index keys of the newest tokens.
This design choice trades memory for communication.
At 10M tokens on GLM-5.3-Flash with context parallelism over 8 GPUs, each rank holds a 1.25 GiB share of the 10 GiB KV cache of a layer and the full 246 MiB bucket cache. 

 We provide further details on kernels in Appendix  F.1 and on parallelism in Appendix  F.2 . 

 3.4 N-LSA 

 Figure 4: N-LSA design. The attention layer of N-LSA, which can be trained from scratch on the next-token loss alone. 

 N-LSA (Figure  4 ) trains LSA natively with the model, using only the NTP loss.
As the model learns with the selection from the start, we cluster the keys of the attention itself, without dedicated index projections.
We use a single key-value head, such that one key per token serves every query head, and score each bucket by the best similarity any query head gives its centroid: 

 s i , b = max h ⁡ q ^ i , h ⋅ c b s_{i,b}=\max_{h}\hat{q}_{i,h}\cdot c_{b} 

 (3) 

 where q ^ i , h \hat{q}_{i,h} is the normalised query of head h h .
We stop the gradient through the selection, and the NTP loss trains the attention projections only through the keys each query attends to, the selected keys plus the sink and the window.
N-LSA therefore adds no parameters to the model and needs no teacher, no index projections and no auxiliary loss. 

 The attention layers of N-LSA use no positional encoding, as is becoming more common in hybrid models, and RoPE could be supported by clustering only the RoPE-free part of the keys, as D-LSA does on Qwen-3.8-27B . 

 4 Evaluation 

 In this section, we describe the models, the methods we compare, and their settings.
Then, we evaluate the accuracy of D-LSA up to 10M tokens, and its performance per attention layer and end to end.
Finally, we show that N-LSA can be trained natively at an accuracy close to full attention. 

 4.1 Setup 

 Models. 
D-LSA aims to keep the accuracy of a model while making its attention significantly cheaper. We compare each model with D-LSA against its baseline attention, in accuracy and in performance.
We demonstrate D-LSA on both a model with full attention ( Qwen-3.8-27B   ( Qwen Team, 2026b ; Qwen Team, 2026c ) ) and one with sparse attention ( GLM-5.3-Flash   ( Z.ai, 2026 ) ). On Qwen-3.8-27B , we also replace the attention with block sparse attention, inspired by QSA  ( Qwen Team, 2026a ) , as a second sparse baseline. We also compare flat to tree search where possible. 

 Methods. 
We compare the following methods: 

 • 

 Full Attention : every query attends to every preceding key, the baseline attention of Qwen-3.8-27B . 

 • 

 Block Sparse Attention (Flat) : sparse attention whose indexer scores every block of four consecutive keys, as in QSA  ( Qwen Team, 2026a ) and GLM-5.3-Flash   ( Z.ai, 2026 ) . 

 • 

 Block Sparse Attention (Tree) : sparse attention whose indexer searches a tree over blocks of the keys of the attention itself, as in HiP  ( Lee et al., 2025a ) and PISA  ( Tang et al., 2026 ) . To represent these methods, we search a tree over blocks of keys directly on the KV cache, without training, which uses the full keys and favours accuracy over performance. We use blocks of eight keys, the most accurate of the sizes we compare (Appendix  E.6 ). 

 • 

 D-LSA (Flat) and   D-LSA (Tree) : D-LSA with a flat search over every bucket centroid and with a tree search over the hierarchy of buckets.
In decode, each request processes one token per step, and the tree search runs its levels one after another, which pays off only when many requests decode together.
As we evaluate one request at a time, D-LSA (Tree) decodes with the flat search (Appendix  F.1 ). 

 • 

 D-LSA (Training-Free) : D-LSA (Flat) with the principal directions of the keys as both projections instead of trained ones. 

 Every trained indexer we compare is distilled in the same way to ensure fairness. 

 Design parameters. 
Table  2 lists the parameters of every method per model.
For D-LSA, we found that a budget of k = 4096 k=4096 long-range keys holds accuracy past 1M tokens better than smaller budgets, and these extra keys cost little next to the scan of the indexer they replace.
On GLM-5.3-Flash , D-LSA (Flat) selects k = 2048 k=2048 long-range keys for queries before position 1M and k = 4096 k=4096 beyond.
We found that the smaller budget keeps accuracy below 1M tokens while making the attention faster.
Tuning the budget further, for example per layer or per request, is left to future work.
A small index space of d ( idx ) = 64 d^{(\mathrm{idx})}=64 dimensions keeps the scoring and the clustering cheap, and we found wider spaces to add little accuracy.

 Indexer distillation. 
We train on 352M tokens of documents of 16k to 1M tokens from seven domains, for 48k steps, each on 128 queries sampled from one document, with a learning rate of 3 ⋅ 10 − 4 3\cdot 10^{-4} .
This is a fraction of the 2.1B tokens of the dense warm-up of DSA.
In Equation  2 , the target A i A_{i} keeps only the 2,048 keys with the most attention weight per query, renormalised over them, while A ^ i \hat{A}_{i} still spans all of ℛ i \mathcal{R}_{i} , and τ \tau is calibrated per layer before the first step.
Unlike DSA, we do not follow the distillation by training the whole model under sparse attention (sparse training), a step D-LSA also supports but we omit here due to its cost.
We provide further details about the composition and construction of the dataset in Appendix  C . 

 Benchmarks. 
We evaluate accuracy in three categories, each with a representative set of benchmarks.
For knowledge, we use MMLU-Pro  ( Wang et al., 2024 ) (a stratified sample of 2,000 questions) and GPQA-Diamond  ( Rein et al., 2024 ) .
For reasoning, we use AIME25 (four repeats) and MATH500  ( Lightman et al., 2024 ) (100 problems).
For long context, we use LongBench v2  ( Bai et al., 2025 ) (60 questions) and the 13 tasks of RULER  ( Hsieh et al., 2024 ) from 4k to 10M tokens (100 prompts per task up to 1M and 20 beyond).
Evaluating each benchmark in full at ultra-long context is prohibitively expensive, and we therefore use the subsets given in parentheses. 

 PaperTrail. 

To better understand model capabilities in a less synthetic ultra-long context setting, we extend RULER with a set of new tasks called PaperTrail.
The tasks are constructed by embedding a trail of fabricated facts in a large collection of scientific papers.
All papers are recent, almost all published after the release date of the models, such that no model could have seen them in training.
A question can only be answered by finding the facts of its trail and connecting them, as in a literature search.
Samples are built in three domains: exoplanets, long-context machine learning and quantum error correction.
The questions come in three tiers of increasing difficulty, where tier 1 recalls a fact from one paper, tier 2 links facts across two papers and tier 3 traces a trail across three or more.
We provide further details about the construction of PaperTrail in Appendix  D . 

 Model sampling. 
We configure each model’s sampling as recommended by its model card with generation up to 163,840 tokens (Appendix  E ).
 Qwen-3.8-27B reaches 10M tokens with YaRN  ( Peng et al., 2024 ) at factor 40 (42 for PaperTrail at 10M), while GLM-5.3-Flash needs no extension as it has no explicit positional encoding. 

 Hardware and serving. 
We serve all models in SGLang  ( Zheng et al., 2024 ) on H200 and B300 GPUs.
To show that D-LSA can be integrated with the main parallelism strategies, we evaluate it with tensor parallelism (TP8) and with context parallelism in both prefill and decode (CP8). We show more details in Appendix  F.2 .
All accuracy measurements use context parallelism wherever the KV cache of a request outgrows the memory of a single GPU. 

 4.2 Accuracy 

 Figure 5: D-LSA accuracy is on par with full attention and sparse attention baselines on downstream tasks. Shown on knowledge, reasoning and long-context tasks up to 10M tokens. Baseline scores are given with their 95% confidence interval. 

 Figure  5 shows that on knowledge, reasoning and long-context tasks, D-LSA stays close to the accuracy of baseline Full Attention on Qwen-3.8-27B and of baseline sparse attention on GLM-5.3-Flash .
PaperTrail further shows how well the models find and connect facts across large collections of scientific papers. 

 Knowledge and reasoning. 
On knowledge, reasoning and LongBench v2, D-LSA stays within the 95% confidence interval of both baselines, even with reasoning growing to tens of thousands of tokens (Appendix  E ).
We further show that D-LSA does not measurably affect the length of the reasoning. 

 Long context. 
On Qwen-3.8-27B , D-LSA (Flat) stays within 5 points of baseline Full Attention up to 1M tokens and exceeds it at 10M tokens, at 63.9 against 59.9 on RULER and 29.1 against 19.8 on PaperTrail.
It also stays above Block Sparse Attention (Flat) on RULER from 128k tokens on, in a fair comparison, as both indexers are distilled the same way. 

 On GLM-5.3-Flash , D-LSA (Flat) stays within 3 points of baseline sparse attention up to 1M tokens, trails it by up to 8 points at 2M to 5M tokens, and is within 4 points on RULER at 10M tokens.
This comparison favours the baseline, which was trained together with the model, while D-LSA (Flat) is distilled from attention that is already sparse (with no finetuning of the base model itself).
On both models, MultiKey 2, MultiKey 3 and CWE fall the most for every method, the baselines included. We break down RULER by task and PaperTrail by tier in Appendix  E . 

 Design comparison. 
D-LSA (Tree) follows D-LSA (Flat) on Qwen-3.8-27B , but loses accuracy past 1M tokens on GLM-5.3-Flash , at 55.8 against 66.8 on RULER at 10M tokens.
Block Sparse Attention (Tree) falls behind from 512k tokens, to about 63 on RULER at 1M tokens on both models, against 78 and 88 for D-LSA (Tree), and we therefore do not evaluate it beyond 1M tokens.
Large blocks fall earlier (Appendix  E.6 ).
D-LSA (Training-Free), without any training, stays close to D-LSA (Flat) on Qwen-3.8-27B , but trails it on GLM-5.3-Flash . 

 D-LSA follows the accuracy of the baselines, showing that our semantic clustering can preserve accuracy up to 10M tokens. However, we do observe a steep drop in accuracy beyond 512k tokens for Block Sparse Attention (Tree). 

 4.3 Performance 

 Figure 6: D-LSA speedup of one global attention layer. 
Prefill and decode speedup over the baseline attention (log scale), Full Attention for Qwen-3.8-27B and Block Sparse Attention (Flat) for GLM-5.3-Flash , required memory at 10M with one index key per block of four keys for Block Sparse Attention (Flat), and prefill scaling up to 100M (log-log), extrapolated beyond 10M (shaded). 

 Next, we evaluate the performance of D-LSA.
We first measure a single attention layer and then the whole model in production serving. 

 Methodology. 
For one layer, we time the whole attention module, including its projections, the indexer and the attention, on a single GPU.
In prefill, we time the last chunk of 32,768 queries before the given context.
In decode, we time one step of one request with CUDA graph enabled (clustering is amortised across the steps).
For the whole model, we serve each method in SGLang with prefill chunks of 32,768 tokens, and measure the time to first token (TTFT) and the time per output token (TPOT) of one request at a time, the median of three requests of 256 output tokens. 

 Figure  6 shows that the prefill speedup of D-LSA grows with the context.
On GLM-5.3-Flash , it rises from 3.5 × \times at 1M to 22.7 × \times at 10M tokens over baseline sparse attention, and on Qwen-3.8-27B to 72.4 × \times at 10M tokens over baseline Full Attention.
Below 1M tokens, the gain is smaller, at 2.1 × \times at 512k tokens, as the scan of every block is still cheap.
Extrapolated beyond 10M tokens, the prefill of D-LSA (Tree) grows subquadratically and overtakes the flat search, and at 100M tokens it is predicted to be more than 90 × \times faster than baseline sparse attention. 

 Decode follows the same trend, with a speedup up to 4.6 × \times over baseline sparse attention and 42.5 × \times over baseline Full Attention at 10M tokens, with D-LSA (Tree) decoding with the flat search.
On B300, D-LSA reaches 12.5 × \times and 42.9 × \times in prefill and 5.2 × \times and 18.4 × \times in decode at 10M tokens. 

 D-LSA also requires less memory for its indexer.
Baseline sparse attention caches an index key for every block of four keys, while D-LSA caches one centroid in its smaller index space for every bucket of about eight keys, together with the id of each key.
At 10M tokens, the index of D-LSA (Flat) takes 246 MiB per layer against 331 MiB in GLM-5.3-Flash and 642 MiB in QSA.
Larger buckets would shrink the index of D-LSA further.

 End-to-end.

 Finally, we evaluate N-LSA, which is trained natively on the NTP loss alone. 

 Setup. 
We train a hybrid model of about 0.5B parameters with 24 layers, in which every fourth layer is an attention layer and the others are Gated DeltaNet layers  ( Yang et al., 2025b ) .
Each attention layer has 8 query heads over a single key-value head of 128 dimensions, without positional encoding.
We pre-train with a standard Warmup-Stable-Decay (WSD) learning rate schedule  ( Hu et al., 2024 ) , on 100B tokens of FineWeb-Edu  ( Penedo et al., 2024 ) at a context of 4k tokens in the Warmup and Stable phases, followed by 12B tokens of LongDocs in the Decay phase, at 128k tokens (Appendix  C ).
We compare N-LSA with Full Attention, Sliding Window Attention (SWA), and the native forms of block sparse attention, NSA  ( Yuan et al., 2025 ) for Block Sparse Attention (Flat) and PISA  ( Tang et al., 2026 ) for Block Sparse Attention (Tree), all in the same model architecture and on the same data.
Every sparse method attends to about 2,560 keys per query.
N-LSA selects k = 2048 k=2048 long-range keys with flat search, next to a window of 512 keys and 4 sink keys.
SWA attends to a window of 2,560 keys and 4 sink keys, NSA attends to 32 selected blocks of 64 keys and a window of 512 keys, and PISA attends to 40 blocks of 64 keys, which always include the first block and the two most recent blocks (window).
We train N-LSA with flat search only, and leave native training with tree search to future work. 

 Figure  7 shows that N-LSA reaches the validation loss of Full Attention throughout the decay phase at 128k token context, at 1.085 against 1.085, while PISA, NSA and SWA trail at 1.100, 1.117 and 1.154.
During pre-training at 4k tokens, all methods stay within 0.004 of each other, as their keys cover most of the context.
Table  4 confirms this on downstream tasks.
On commonsense reasoning  ( Clark et al., 2018 ; Zellers et al., 2019 ) , all models are on par.
On recall  ( Arora et al., 2024 ) , N-LSA stays close to Full Attention and ahead of the other sparse methods.
On RULER, N-LSA stays within 3.5 points of Full Attention up to 128k tokens, at 32.2 against 34.7 at 128k tokens, while NSA and PISA fall to 19.2 and 14.6, and SWA to 3.0 once the context outgrows its window. 

 N-LSA also trains faster than Full Attention at long context.
For one attention layer on a single GPU, the forward and backward pass of N-LSA is 1.1 × \times faster than Full Attention with FlashAttention-3  ( Shah et al., 2024 ) at 64k tokens and 1.6 × \times faster at 128k tokens (Figure  7 , left).
End to end, the whole model completes its decay phase 1.24 × \times faster at the same validation loss (Figure  7 , right), as only every fourth layer is an attention layer.
At shorter contexts, the selection of the keys costs more than it saves.
Its peak memory is higher, at 6.8 GiB against 5.8 GiB per layer at 128k tokens, partly because N-LSA keeps the indices of the selected keys of every query for the backward pass, which grow linearly with the context. 

 Overall, N-LSA trains natively at the accuracy of Full Attention and becomes faster as the context grows. 

 5 Discussion 

 LSA reduces the cost of finding the keys, but not of storing them, and the KV cache still grows linearly with the context.
It is orthogonal to methods that compress the KV cache  ( DeepSeek-AI, 2026a ) , share the index across layers  ( Bai et al., 2026 ; DeepSeek-AI, 2026b ) , or predict several tokens per step  ( Gloeckle et al., 2024 ; DeepSeek-AI, 2024 ) , and could be combined with each. 

 We observed tree search to lose accuracy faster than flat search past 1M tokens on GLM-5.3-Flash , while it overtakes flat search in decode only from about 5M tokens with one request, and is predicted to do so in prefill only beyond 10M tokens.
It remains open whether sparse training would close this gap beyond indexer distillation. 

 We train N-LSA at a small scale, with about 0.5B parameters, up to 128k tokens and with flat search only.
Scaling native training to larger models, longer contexts and tree search remains open. 

 6 Conclusion 

 At ultra-long context, the cost of sparse attention lies in finding which keys to attend to.
We introduce LSA, which clusters the keys in a learned latent space and replaces the scan of every key with a search over the clusters, flat or along a tree.
D-LSA distils LSA into pre-trained models and stays close to the accuracy of their baseline attention up to 10M tokens.
At 10M tokens, one attention layer of D-LSA prefills 22.7 × \times and decodes 4.6 × \times faster than sparse attention in GLM-5.3-Flash , and 72.4 × \times and 42.5 × \times faster than Full Attention in Qwen-3.8-27B .
End to end, this reduces the time to first token by 2.2 × \times and 9.2 × \times , respectively.
N-LSA trains LSA natively on the next-token loss alone, at the accuracy of Full Attention and 1.6 × \times faster per layer at 128k tokens.
With tree search, the cost of finding the keys grows subquadratically, which makes LSA a step towards attention that scales well beyond 10M tokens.
LSA thus provides a practical way forward for ultra-long context attention, both for distilling pre-trained models and for native training.

 Appendix A Attention Sparsity 

 To test how many keys a query needs to keep accuracy, we let each query of Qwen-3.8-27B attend only to the sink, the window and its true top- k k keys (Figure  8 ).
At 128k tokens, Top- k k Oracle Attention keeps 98% of the RULER accuracy of Full Attention down to k = 512 k=512 , while each query attends to 0.8% of the keys.
Single-needle retrieval holds down to k = 16 k=16 , while MultiKey 2, MultiKey 3 and CWE fall first in accuracy.
Therefore, sparse attention loses little if it finds the most relevant keys, which is what LSA is designed to do without scoring every key.

 Appendix C Training Data 

 In this section, we report additional details on the training dataset we use to train D-LSA under indexer distillation, and also train N-LSA in the decay phase: LongDocs . 

 We use the following terminology: 

 • 

 Source : a collection of documents, such as Project Gutenberg. 

 • 

 Domain : a group of sources: books, academic, code, agentic, government, parliament and discussion. 

 • 

 Document : one item of a source, such as a book, a paper, a code repository or an agent trace. 

 • 

 Sequence : a contiguous part of one document, at a particular sequence length from 16k to 1M tokens. 

 Figure 9: LongDocs. 
Tokens of the distillation mix by domain and source (left) and by sequence length (right), with the in-house agent traces hatched. 

 Sources. 
LongDocs is a collection of long documents from publicly available sources and in-house agent traces.
Eight sources are publicly available: Project Gutenberg, DOAB, arXiv, USGPO, UK Hansard and Wikimedia from the filtered releases of the Common Pile  ( Kandpal et al., 2025 ) , The Stack  ( Kocetkov et al., 2023 ) , of which we take the Python and Java repositories, and the software engineering traces of Open-SWE-Traces  ( NVIDIA, 2026e ) .
The in-house agent traces are long sessions of agents that play games or solve long-context tasks, and they make up 13.1% of the training tokens.
We use every public source as released. 

 Sequences. 
Each sequence comes from one document and never joins two documents.
A code document is one repository, its files joined in the order of their paths, and an agent trace is one session rendered as text.
We hold out 2% of the documents for validation. 

 Distillation training. 
We distil every indexer on a mix of 352M tokens drawn from LongDocs (Figure  9 ).
The mix is uniformly sampled across domain and sequence length, with a bias towards longer context windows at 512k and 1M. In particular, we give each sequence length 32M tokens, and twice and four times as many to 512k and 1M. Sequences of 1M tokens thus hold about a third of the training tokens. We experimentally determine this choice to be beneficial, with +0.036 accuracy on RULER at 1M (averaged over 3 seeds, notable lifts in multikey_2 , multikey_3 , +0.35 and +0.15 respectively), while accuracy from 4k to 512k stays roughly identical.
Within each length, every domain receives an equal share of the tokens.
A domain with too few documents of that length gives its share to the others (parliament stops at 256k tokens and discussion at 512k). 

 Native training. 
The decay training stage of N-LSA reads the whole collection rather than the mix, without the long-context agent sessions.
The data is tokenised (18.9B tokens over 134,740 documents), and cut into sequence lengths the training requires. 

 Appendix D PaperTrail 

 As part of this work, we introduce PaperTrail, an extension of the RULER  ( Hsieh et al., 2024 ) benchmark that tests models at ultra-long context in a more realistic setting, inspired by real-life scientific literature review (Figure  10 ).
Instead of finding a needle in synthetic text, a model finds facts spread across real scientific papers and connects them, as in a literature search.
We use the following terminology: 

 • 

 Sample : a collection of real arXiv preprints of 2026 from one domain. 

 • 

 Trail : a chain of papers that introduces a result, cites it, and later revises and renames it. 

 • 

 Fabricated paper : a paper we write for a trail. 

 • 

 Host paper : a real paper into which we insert passages that cite or use facts from a fabricated paper. 

 • 

 Insertion : a passage we add to a host paper, which only adds sentences and never changes the text of the authors. 

 • 

 Background paper : any other paper of a sample, real and unchanged. 

 Figure 10: PaperTrail. 
 1 A sample, its fabricated, host and background papers.
 2 One trail, introduced, revised and renamed, and still quoted in its old form after the revision.
 3 Questions by tier, and one whose answer is not in the papers.
 4 Context sizes, each holding every paper of the size below.
 5 Controls. 

 Figure 11: D-LSA accuracy on RULER individual tasks. The 13 tasks of RULER from 4k to 10M tokens on Qwen-3.8-27B and GLM-5.3-Flash , by task group, with their average. 

 1 
 Context. 
PaperTrail has three samples, on exoplanets , long-context machine learning and quantum error correction , with 1,246 papers in total.
Each sample hides two trails (Trail A and Trail B).
A trail has two fabricated papers and 8 to 9 insertions in 6 to 7 host papers, and background papers fill the rest of the context.
An insertion places its references where an author would place them, such that a host paper reads naturally as before.
Papers in the context are not presented in chronological order, and a host often comes before the paper it cites. 

 2 
 Trails. 
The first fabricated paper of a trail introduces a result, for example AlloKV, a KV cache eviction method whose budget grows as the 0.43 power of the context length.
Host papers cite and use it.
Two to three weeks later, the second fabricated paper revises the value and renames the method, here to SuBA with an exponent of 0.61.
Host papers posted after the revision either cite the new name or still quote the old value, as real literature often does. 

 3 
 Questions. 
Each sample asks 30 scored questions, 10 per tier.
A tier 1 question recalls a fact from one paper, a tier 2 question links two papers, and a tier 3 question links three or more papers, often the whole trail.
Each sample also asks 6 questions whose answer is not in the papers, about an absent entity, a false premise or a near miss, which we report apart from the score (Table  8 ).
The model ends its reply with the papers it used and its answer.
A number counts within a relative tolerance of 2% by default, and a set of papers is scored by its F1 against the reference set. 

 4 
 Context sizes. 
We build each sample at 512k, 1M, 2M, 5M and 10M tokens, and every size holds every paper of the size below.
The fabricated and host papers, at most 18 per sample, are the same at every size.
The background papers grow the context from 25 to 30 papers at 512k to 386 to 465 papers at 10M, and spread the trails over the whole context.
The trails are fabricated, and every paper up to 5M was posted after the release of both Qwen-3.8-27B and GLM-5.3-Flash , guaranteeing that no model has seen these papers in training.
The 10M contexts hold papers posted at most six weeks before its release. 

 5 
 Controls. 
Four controls ask the same questions over parts of a sample: the question alone, the host papers without their insertions, the fabricated papers with the insertions alone, and the background papers alone.
By construction, only the fabricated papers and the insertions hold the answers.
We validate the controls with GLM-5.3-Flash and D-LSA (Training-Free) in Table  8 .

 E.6 Block Size 

 Figure 14: Block size of Block Sparse Attention (Tree). 
RULER and PaperTrail up to 1M tokens with blocks of 8, 16 and 64 keys ( n pool n_{\mathrm{pool}} ), each selecting the same 4,608 keys, against the baseline of each model and D-LSA (Flat).

At short context, every block size matches the baseline.
As the context grows, accuracy falls earlier and further the larger the block, on both benchmarks and both models, as a larger block summarises more keys in one score and can hide a single relevant key.
Even with blocks of eight keys, the size we use in the main results, the tree baseline trails D-LSA (Flat) at long context.

 Precision. 
The KV cache, the index keys and the bucket centroids are in bf16.

 3 
 Clustering. 
The clustering does relatively little work: one Gram matrix per cluster block, over its pooled keys, takes about 0.13 Gflop for a whole chunk, against 5.5 Tflop for the bucket scan at 10M tokens.
Ward’s method, however, merges buckets in rounds that run one after the other.
Each of these rounds scores every pair of buckets and merges the cheapest mutual pairs (Algorithm  1 , lines  5 - 11 ), until m m buckets remain.
The overall runtime of the clustering step is therefore set by the latency of these rounds.
Our kernel cuts the time of each round by keeping its data on chip and avoiding round trips to the host between rounds.
More precisely, the kernel keeps the state of a cluster block in shared memory for all its rounds, and spreads its search for partners over a thread-block cluster of up to eight streaming multiprocessors (SMs), which exchange their results through distributed shared memory.
In D-LSA (Tree), each pairing that forms the node buckets (line  16 ) runs all its rounds in a single launch, whose thread blocks synchronise through counters in high-bandwidth memory (HBM), so the host neither launches nor reads anything between rounds.

 Selection by threshold. 
D-LSA scores an index query q i ( idx ) q_{i}^{(\mathrm{idx})} against the centroids c b c_{b} of the buckets ℬ i \mathcal{B}_{i} of the cluster blocks before its own, and keeps its top- p p buckets.
Over the index queries of a chunk, the scores s i , b = q i ( idx ) ⋅ c b s_{i,b}=q_{i}^{(\mathrm{idx})}\cdot c_{b} form a matrix with one row per query, so we call the scores of query i i its row , in decode as well.
The row holds N i = | ℬ i | N_{i}=\lvert\mathcal{B}_{i}\rvert scores, which grows with the position of the query, to about T / n ¯ b T/\bar{n}_{b} at the end of a context of T T tokens.
In prefill and in decode alike, many thread blocks compute the scores of a row, each over its own span of the row, so no thread block sees the whole row, and the selection cannot take its top- p p directly.
Instead, inspired by Floyd & Rivest (1975) (who select from only the elements between two bounds estimated from a sample), before the scan, we set a threshold θ i \theta_{i} for each query, and a thread block compares each of its scores with θ i \theta_{i} .
Then, it appends only the buckets whose score is at or above it to the list L i L_{i} of the query: one comparison per score, without seeing the rest of the row.
Only the buckets of L i L_{i} , a small multiple γ ​ p \gamma p of them (see below), are then ranked. 

 We also evaluate an alternative inspired by the k-selection of FAISS  ( Johnson et al., 2021 ) , which keeps the top- p p buckets of each span and merges them.
With this design, every thread block has to rank its span, rather than compare each score once.
Furthermore, the merge receives p p buckets from every span, rather than about γ ​ p \gamma p in all.
Overall, at 10M tokens in prefill, a row is split into 320 spans, which list 327,680 buckets, against about 1,536 in L i L_{i} . 

 We aim for about γ ​ p \gamma p buckets of the row to score at or above θ i \theta_{i} , with γ > 1 \gamma>1 : enough to hold the top- p p with room for error, and few enough to keep L i L_{i} short.

 CUDA graphs. 
A prefill chunk takes milliseconds, against which the launches of its kernels from the host cost little, and its selection reads the sizes of its lists back on the host, so we serve prefill without graphs.
A decode step of the selection, however, takes only tens of microseconds, about as long as its launches, so SGLang captures each decode step, our kernels included, in a CUDA graph, and replays it with one launch from the host.
A CUDA graph fixes the shapes of its kernels, so a graph sized for the longest context the server admits would launch the thread blocks of 10M tokens at every step, whatever the contexts of the batch.
We therefore capture one graph per range of context lengths, up to 1.125 ⋅ 2 e 1.125\cdot 2^{e} tokens for e = 17 , … , 23 e=17,\ldots,23 (from 144k to 9M), and one graph for the longest context, and each step replays the narrowest graph that covers the longest request of the batch.
The threshold estimate of the flat search samples across the width of the graph, so a request far shorter than its range would see too few samples and fall back to its full row.
The factor 1.125 avoids this for the common case: a request of a power-of-two length, with its answer, sits at about 89% of its range.
The clustering of a complete cluster block runs outside the graph, before the replay, once every n cluster = 512 n_{\mathrm{cluster}}=512 decoded tokens, and the decode times of Section  4.3 spread its cost over those tokens.

Prefill, bound by compute, can afford to read the centroids more than once: every tile of queries reads them all, and candidate scoring reads those of L i L_{i} again.
In decode, a second read would about double the bytes the scan reads, so Algorithm  4 selects within a single read of the centroids, besides the small sample of its threshold estimate.
It can, however, afford to write every s i , b s_{i,b} to HBM, which adds only 3% to the bytes it moves, so that its fallback takes the top- p p of the written scores, without reading the centroids again.
The threshold is thus not strictly needed in decode, but it saves a selection over all N i N_{i} written scores of each request: the expansion ranks only the buckets of L i L_{i} . 

 With a single query, only the row is split: the scan takes spans of 256 buckets, one per thread block.
The centroids of a request lie in pages of B cache ( idx ) B_{\mathrm{cache}}^{(\mathrm{idx})} , as its keys lie in pages of the KV cache, and each thread block reads the c b c_{b} of its span through the page table of the request.
The threshold estimate and the scan score on the CUDA cores, with the same dot product: at 1 flop/B the scan is bound by HBM, not by arithmetic, and gains nothing from tensor cores.
A request whose row fits in its list takes every bucket. 

 Each CUDA graph samples a fixed number n s n_{s} of buckets, from 2,048 to 16,384, in runs of 8 neighbouring buckets of a page, spread evenly over the row.
A graph that covers longer contexts thus samples a smaller share of the row, with a smaller n θ n_{\theta} and a noisier estimate, so the target γ ​ p \gamma p grows with the graph, from 1.5 ​ p 1.5p to 3 ​ p 3p .
We set γ \gamma for each graph by hand, so that L i L_{i} still holds at least p p buckets, and fits in its buffer, when the count misses γ ​ p \gamma p by four times the deviation above, 4 ​ γ ​ p / n θ 4\gamma p/\sqrt{n_{\theta}} .
Algorithm  4 runs in four launches, followed by the expansion, and has no candidate scoring.
The threshold estimate takes two launches: one scores the sample, and one finds its n θ n_{\theta} -th best score by radix select over the bits of the scores, and rounds it down (lines  1 - 2 ).
The bucket scan writes the s i , b s_{i,b} of each span, and appends the buckets with s i , b ≥ θ i s_{i,b}\geq\theta_{i} to L i L_{i} , already packed as σ i , b \sigma_{i,b} (lines  3 - 6 ).
It compares the very scores that rank the buckets, so it needs no margin.
The listing gathers into L i L_{i} the spans that the thread blocks appended, in bucket order (line  7 ), and the expansion is that of Algorithm  3 (line  9 ).
The list L i L_{i} has room for 2,048 to 8,192 buckets, by graph, and a request whose list overflows, or holds fewer than p p buckets, falls back to the top- p p of the scores the scan wrote (line  8 ).
Programmatic dependent launch  ( NVIDIA, 2026f ) , a feature of Hopper and Blackwell GPUs, lets a kernel start while the one before it still runs, and wait for its results only where it reads them (line  5 ).
The scan thus reads and scores the centroids while θ i \theta_{i} is still being computed.

 Tree prefill. 
In prefill, the beam search (Algorithm  2 ) starts at the lowest level with at most n start = 32768 n_{\mathrm{start}}=32768 node buckets, a value we chose by a sweep of accuracy against time.
It keeps a beam of p ℓ = 2048 p_{\ell}=2048 node buckets on every level.
The descent starts from every node bucket of this level (line  1 ), which one matrix product in cuBLAS scores in full.
Each level of the descent (lines  2 - 7 ) then runs in one kernel (five or six launches in Triton), besides a matrix product in cuBLAS that scores the open node buckets of the level.
In this kernel, a thread block holds the scores of one query in shared memory, one 32-bit word per candidate, up to the 227 KiB a thread block can take.
It scores the children of the node buckets kept on the level above (line  3 ).
It then finds the p ℓ p_{\ell} -th score by a radix select of four passes, each of which counts one byte of the words in a histogram of 256 bins (line  4 ).
Finally, it writes the children of the node buckets it keeps as the candidates C C of the next level (line  5 ).
Above about 24k node buckets, keeping the beam of the start level this way would leave a single thread block per SM, so it takes two launches instead: a listing of the node buckets above a sampled threshold, as in the flat search, and the keep of the beam.
At level 0 (lines  8 - 9 ), the thread block writes the top- p p buckets as packed scores σ i , b \sigma_{i,b} .
The expansion of Algorithm  3 (lines  13 - 16 ) reads them as it reads L i L_{i} . 

 B 
 Tree decode. 
In decode, the new queries of all the requests of a batch descend together, through the beam kernels of the prefill, but over a copy of the hierarchy at fixed addresses, and at shapes set by the longest context, so that a CUDA graph can replay the step.
Each request adds one query per step, but the descent still runs its levels one after another, so its time barely changes with the number of requests, while the flat search scans every bucket once per request.
Every query scores the levels from the top level of the longest context down, and holds no candidates above its own start level.
A step takes 7 to 13 kernels from 128k to 10M tokens, as the number of levels grows with the context.

 Other steps. 
The remaining steps of D-LSA are the projections and the L2 normalisation of the index keys k j ( idx ) k_{j}^{(\mathrm{idx})} and queries q i ( idx ) q_{i}^{(\mathrm{idx})} , the pooling, and the tables of B cache ( idx ) B_{\mathrm{cache}}^{(\mathrm{idx})} .
They consist of matrix products, reductions and a sort, which run as standard PyTorch operations, with the products through cuBLAS.
These steps cost little next to the scoring.
On GLM-5.3-Flash , for example, each of the two projections of a chunk of 32,768 tokens from the 512 dimensions of the latent takes 2 ⋅ 32768 ⋅ 512 ⋅ 64 2\cdot 32768\cdot 512\cdot 64 flop, 4.3 Gflop for both.

D-LSA attends through existing kernels, which only need to read the index lists in a layout of their own.
The expansion writes the index list J i J_{i} of every query i i as a row of n sink + k + n w = 4612 n_{\mathrm{sink}}+k+n_{w}=4612 int32 entries.
Each entry is the slot in the KV cache of one key j ∈ J i j\in J_{i} , and the row is padded with − 1 -1 when the query has fewer keys to attend to.
The index lists of a chunk 𝒞 \mathcal{C} thus form one matrix of | 𝒞 | \lvert\mathcal{C}\rvert rows.

 N-LSA training. 
The kernels above serve D-LSA at inference.
N-LSA also needs kernels for training, for its forward and its backward pass, with which a layer is up to 1.6 × \times faster than with Full Attention at 128k tokens (Section  4.4 ). 

 A few changes stem from the architectural differences of N-LSA compared to D-LSA.
A training step processes whole sequences, of up to 128k tokens in our runs, with no KV cache and no decode, so every query of a sequence selects at once, as in a prefill chunk as long as the sequence.
The keys change at every step as the attention projections learn, so every step clusters all keys again, where D-LSA clusters each cluster block once and keeps its buckets in the cache.
The selection clusters and scores the attention’s own normalised keys and queries, of dimension 128, and takes the best score of the 8 query heads (Equation  3 ).
At 128k tokens, a row holds at most 16,384 buckets, from which a query selects p = 512 p=512 for k = 2048 k=2048 keys, next to a window of 512 keys and 4 sink keys.
Finally, every step runs a backward pass, which D-LSA never does at long context. 

 Two of these differences shape the kernels.
As the rows are short, the selection places θ i \theta_{i} from the whole row rather than from a sample: a first pass over the row counts its scores in a histogram of 256 bins, and a second lists the buckets from the bin of the p p -th score up, both on tensor cores, and the top- p p of the list are then taken by their scores.
The backward pass is the main addition.
As N-LSA stops the gradient through the selection, the clustering and the scoring of the centroids need no backward pass, and the only new backward kernel is that of the sparse attention.
For one query head, with logits z i , j = q i ⋅ k j / d h z_{i,j}=q_{i}\cdot k_{j}/\sqrt{d_{h}} , its forward pass, as in any attention kernel, runs over the queries, each query i i attending to the keys it selected and writing only its own output:

 Context parallelism. 
CP splits work by token in two ways  ( Liu et al., 2024 ; Yang et al., 2025a ) , which we describe in the following, and illustrate in Figure  19 . 

 Decode context parallelism (DCP), also called KV parallelism  ( Bhatia et al., 2025 ) , splits the KV cache across the ranks, in both prefill and decode, so that each rank stores only 1 / N 1/N of it, which lets a context of millions of tokens fit in HBM, and reads only its share in each decode step.
SGLang deals the tokens out round-robin: token j j goes to rank r j r_{j} , its slot in the KV cache modulo N N , and that rank holds key k j k_{j} and thus computes index key k j ( idx ) k_{j}^{(\mathrm{idx})} . 

 Prefill context parallelism (PCP) also splits the query rows of a chunk 𝒞 \mathcal{C} , giving rank r r the rows 𝒞 r \mathcal{C}_{r} , so that it selects the index lists J i J_{i} of its own rows i ∈ 𝒞 r i\in\mathcal{C}_{r} only.
The index query is not split: with PCP, every rank holds in prefill all n h n_{h} query heads q i , h ( attn ) q_{i,h}^{(\mathrm{attn})} of its rows, and in decode (and with GQA also in prefill), the ranks gather them, as the attention does anyway, so every rank computes q i ( idx ) q_{i}^{(\mathrm{idx})} itself. 

 We extend SGLang with PCP for GLM-5.3-Flash , which leaves us free to choose its layout, for both the base model and LSA.
We make each 𝒞 r \mathcal{C}_{r} one contiguous span of 𝒞 \mathcal{C} , which lets the linear-attention layers pass their recurrent state along it.
LSA does not depend on this split, but it is a natural fit: as every query attends a fixed budget of keys, a contiguous split already balances the sparse attention across ranks, whereas dense causal attention commonly uses a zigzag or striped split to balance its causal work  ( Brandon et al., 2023 ; Yang et al., 2025a ) .
