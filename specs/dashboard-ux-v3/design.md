# Dashboard UX v3 — 任务导向控制台改版设计

- 状态：**草案（待用户验收样机后定稿）**
- 日期：2026-11-27
- 裁决记录：2026-11-27 用户四项裁决 —— ①不满=层级乱+高频操作太深+缺像样页面+观感不专业+聚类不合理（全选）；②范围=**结构重构·保栈**；③IA=**5 区任务导向**；④视觉=**暖浅色微调**（维持 11-03 暖瓷白拍板）。
- 二轮裁决（2026-11-27，样机评审）：**模型页内部分层重排** —— 模型分本地/云端两大类；本地再按独占/共享分，云端按厂商分；**模型池与两者并列且置顶**（用户高频：快速切换 + 优先级顺序调整，池改动对多 agent 即时生效）；池的界面设计须基于其真实功能（fabric-四角色、候选链、优先级调序、五态灯、CAS）。整体风格与 5 区分类维持不变。
- 三轮裁决（2026-11-27，样机复评，**推翻二轮的"池置顶于模型页"**）：池上提后本地/云端清单被压深——**模型池独立成导航项「路由」，导航 5→6**（状态 / 请求 / 用量 / 路由 / 模型 / 配置）；模型页只保留本地/云端模型清单与在池提示。
- 本设计**推翻**：console-ux-batch WS4 的 10 项导航分组（2026-11-24）；dashboard-v2-console 的六 TAB 结构与"监控页纯遥测"定位。其余未提及的已定案决策（零构建、双层令牌、CVD 色板、暖色默认、确认弹窗规范、本机零门槛）**继续有效**。
- 样机：`specs/dashboard-ux-v3/preview.html`（示例数据，非实现）。

## 1. 意图与为什么

当前界面按**实现模块**切导航（监控/异常/推理/模型池/能力包/鉴权/设置/云端/接入/总览），用户带着**任务**来（看态势、切模型、查请求、看用量、改配置），任务与页面错位：高频操作埋两层、请求日志是网关第一资产却没有页面、排障横跨三页、配置类占侧栏一半。本次以"用户任务→界面"重排信息架构，吸收 opencodex proxy dashboard 的六个可用模式，在既有暖浅色令牌体系内做专业质感刷新。

用户：单一用户（vincent），双机使用——Mac（darwin-arm，无 GPU，观察+配置）与 vince-pc（RTX 5090D，GPU 主场）。控制台由 Python proxy 直接 serve（`127.0.0.1:8999`），零构建。

## 2. 目标 / 非目标 / 反目标

**目标**
1. 导航 10 → 6：**状态 / 请求 / 用量 / 路由 / 模型 / 配置**，每项对应一个任务动词（三轮裁决：模型池独立为「路由」）。
2. 请求日志升为一等公民页（Live、失败标红、过滤、列选择、行展开、切换历史与异常事件并入为子页）。
3. 状态页承载态势陈述 + 当前模型高频操作（停止/休眠/切换一键直达）+ 硬件遥测（无 GPU 主机自动降级为网关健康卡）。
4. 用量页以**一个**全局时间范围控件驱动：KPI band（请求/Tokens/成本/缓存命中）→ 图 → 按模型/按客户端分解。
5. 模型页收敛"推理+模型池"边界：运行控制区 + 引擎指标 + 池管理。
6. 配置区（云端/鉴权/接入/能力包/系统）收进一个导航项下的二级导航。
7. 暖浅色令牌体系内：排版层级、密度节奏、组件统一、空态设计、术语统一。

**非目标**
- 不改后端转发核心（PR-14 红线）；不引入前端构建链/框架（零构建定案）；不做登录/多用户（本机零门槛不变默认）；不做 ⌘K 全局搜索（5 项导航无此刚需）；不引入 WebSocket（快照轮询+ETag 机制保留）。

**反目标（做了一定是错的）**
- 重新引入"每图各配粒度控件"的多控件并存；把维护操作（释放 GPU/强制重置）放回首屏常驻按钮；用状态色做图表系列色。

## 3. 信息架构

### 3.1 侧栏
- 200px 宽文字导航（可折叠至 56px 图标栏，记忆于 localStorage）。6 项无分组标题；底部状态区：版本/rev/在线点/主题切换。
- Hash 路由：`#/status` `#/requests` `#/usage` `#/routing` `#/models` `#/config`，子页 `#/requests/switches` `#/requests/anomalies` `#/config/cloud` 等。刷新与跳转保持位置；状态页"最近请求→查看全部"可带过滤参数跳转。

### 3.2 五区明细

**状态（#/status）** — 回答"现在怎么样、要动什么"
- 态势条：状态点 + 一句话（`运行中 · qwen36-27b · 今日 1,284 请求 · 2 warning`）+ 最近同步时间。
- 当前模型卡：模型名/引擎/端口/已运行时长 + 操作（停止/休眠/切换）。空闲时显示常用模型一键切换（最近 3 个）。
- 硬件遥测带：GPU 在场 → 五段遥测（VRAM/利用率/功耗/温度/时钟）；无 GPU 主机（Mac）→ 降级为网关健康卡（统一内存/在线时长/版本）+ 一行说明"遥测在 GPU 主机查看"。
- 最近请求卡（Live）：最近 5 条 + 成功/失败计数，"查看全部"→ 请求页。
- 维护菜单（▾ 收纳）：释放 GPU / 对账 / 重载配置 / 强制重置（danger，确认弹窗保留）。

**请求（#/requests）** — 回答"发生过什么"
- 子页 segmented：**请求 / 切换历史 / 异常**。
- 请求表：Live 开关、计数行（`1,284 条 · 24h · 37 失败` 失败标红）、过滤行（时间范围/状态/模型/客户端/搜索）、列选择（时间/状态/模型/客户端/tokens/耗时/缓存）、行展开显示路由决策（local/cloud、目标端口、重试次数、异常关联、请求 id）。
  - **builder check 裁决（2026-11-27）**：①「协议」列取消——request_log 未记录协议，从 UA 推导不可靠，不为此开转发核心写路径例外；②行展开的重试次数/目标端口仅池路由请求可显示（`metadata.pool_summary` 读侧透出），非池请求显示「—」，不伪造；③「异常关联」用模型+时间窗+状态的启发式关联，界面明示「按模型/时间推断」；④过滤行与真实计数需 `/api/request_log` 读侧扩展（见 §5）。
- 切换历史：现监控页 col-4 表整体迁入。
- 异常：现异常页整体迁入（4 严重度 tile + 过滤 + 结构化事件表）。

**用量（#/usage）** — 回答"花了多少"
- 全局时间范围控件（1h/24h/7d/30d）一页一个。
- KPI band：请求数 / Tokens / 估算成本 / 缓存命中，各带 sparkline + 一行副标题。
  - **builder check 裁决（2026-11-27）**：「缓存命中」口径 = **KV 前缀缓存命中份额**（请求日志 `tokens_in_cached` 的 token 加权读侧聚合），副标题注明口径；响应缓存命中率需在转发路径加 miss 计数器（写路径），不做。
- 每日堆叠柱图（本地/云端，系列色固定 蓝/琥珀）。
- 分解表：按模型（share 条/tokens/请求数/成本/延迟 p50/p95）与按客户端（agent 认领/未识别）。
- 原监控页功耗双轴图取消（功耗即时值在遥测带保留；电费并入成本 KPI）。

**路由（#/routing）** — 回答"请求按什么顺序被选择与回退"。**2026-11-27 三轮裁决：模型池自模型页升为独立导航项（用户高频：快速切换 + 优先级顺序调整，池改动对多 agent 即时生效）；界面按其真实功能设计。**
- **模型池**：按四角色固定序（fabric-flash / max / lite / classifier）每池一卡——池头：五态灯（调用中/冷却中/故障/空闲/未配置）+ 策略徽标（按序回退= priority_failover / 仅首选= first_only）+ 角色说明 + enabled CAS 开关；候选链：按优先级排序，每行 = P 序号 + 五态灯 + 目标 + 本地/云 + 协议徽标 + 视觉标 + 在役「调用中」高亮 + 延迟心跳图 + ↑↓✕ 行内调序/移除；池底：添加候选 / 编辑池（三段式编辑器模态原样保留）+ revision/CAS 提示；页级 dry-run 预演入口。
- **视图切换**：卡片视图 / 链路树（复用现网调用树渲染：`:8999 → fabric-〈角色〉 → 候选链`，在役高亮）。

**模型（#/models）** — 回答"有哪些模型、谁在跑"。
- 引擎指标条：KV Cache/Seq Length/TPOT/TTFT/吞吐（页顶，仅本地有运行中引擎时显示）。
- **本地模型**：独占（一次一个，占满 GPU）/ 共享（并存小模型）两组行卡，操作 切换/停止/休眠/唤醒，每行附「在池」关联提示（该模型出现在哪些池的哪一优先级）+ 跳转路由页。
- **云端模型**：按云厂商分组卡（已连接 pill），每模型行 = 可路由开关 + 已入池提示；厂商连接与密钥管理留在 配置区·云端（模型页只管"模型"，配置区只管"连接"）。
- 部署入口 → 配置区·能力包。

**配置（#/config）** — 低频但找得到
- 页内左侧二级导航：**云端 / 鉴权与密钥 / 接入 / 能力包 / 系统**。
- 云端=现云端页；鉴权与密钥=现鉴权页；接入=现接入页；能力包=现能力包页（部署向导为唯一主入口，legacy 表单保持折叠）；系统=现设置页（授权三卡）+ **网关控制卡（LRU 缓存/自动切换/限流，自模型页移入——属运行时策略而非模型本体）** + 关于（版本/rev/OpenAPI 链接）。

## 4. 视觉（暖浅色令牌内微调）

令牌体系不动：三层（primitive→semantic→组件）、暖瓷白 `#f5f3ee`/暖炭黑 `#16130e`、铜 accent `#b45a3c`(light)/`#d98e6e`(dark)、状态色 4 枚、图表系列色固定 `['#2563eb','#b45309','#0891b2','#15803d','#db2777']`。改动点：

1. **侧栏**：56px 图标栏 → 200px 文字导航（最大观感变化）。
2. **卡片语法统一**：标题区（标题+一行说明+右侧动作区）；1px 边框、radius 10、零拟物阴影（沿既有原则）。
3. **状态 pill 组件**：idle/running/sleeping/error/warning 统一形状与配色，全站复用。
4. **空态设计**：无模型/无 GPU/无请求/池为空——每处一句话说明"这是什么+下一步动作"。
5. **术语表**（全中文，专有名词保留英文）：Reconcile→对账、Deploy→部署、Auto-switch→自动切换；GPU/VRAM/KV Cache/TTFT/TPOT/tokens 保留。
6. **表格密度规范**：行高 40px、1px 分隔、hover 高亮、数字列 tabular-nums 右对齐。
7. **a11y 遗留修复**：dark 下 `#fff` on accent 2.61:1 < AA（v2 spec 遗留观察项）——定稿方案：**on-accent 令牌在 dark 下改深色字（accent 色相不动，2026-11-03 拍板不推翻）**，样机已按此实现。

## 5. 技术方案（保栈）

- **文件组织**：沿用 fragments + js 模式，按新 5 区重组：`status.html`、`requests.html`、`usage.html`、`models.html`、`config.html`（config 壳 + cloud/security/connect/packs/system 五个子 fragment，页内二级导航切换）。JS 对应拆分，`store.js` 快照轮询（3s+ETag）保留。
- **轮询收敛**：全局快照 3s 为主；能力包 2s→跟随全局；向导运行期间 2s、关闭即停；用量图表数据按需拉取（时间范围变更时）。
- **hash 路由**：新增轻量 router（约 60 行，无依赖）；`switchTab` 改由 router 驱动，带子页与过滤参数。
- **读侧 API 扩展（builder check 裁决，2026-11-27）**：允许只读扩展 `proxy/handler.py`、`monitor_report.py`、`dashboard/__init__.py`——request_log 过滤参数与总数、`req_id` 透出、`metadata.pool_summary` 透出、monitor-report 按模型成本拆分、`tokens_in_cached` 窗口聚合。**转发核心（chat_handlers / forwarder / 响应缓存写入路径）零改动**，PR-14 红线不破；涉及的敏感上游错误文本不透出（终审 #16 沿用）。
- **测试**：新增 fragment 引用完整性单测（base.html 的 FRAGMENT/JS 占位与文件一一对应）；其余沿用手测 + runtime smoke。

## 8. 被否的备选

- **增量修补**（保 10 项 IA 逐点改）：模块式切分的根子不变，用户裁决不选。
- **全面重写**（Vite/React 构建链）：推翻零构建定案，双机协作与 Python 直发成本不成比例，用户裁决不选。
- **中性极简/深色优先视觉**：用户裁决维持暖浅色体系。
- **6 区（异常独立）**：异常事件本质是"发生过什么"的一部分，并入请求页子页后少一项导航且动线更短；用户选了 5 区。
